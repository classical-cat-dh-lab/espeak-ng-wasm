# Building (BUILDING.md)

> Reproducible build pipeline: upstream eSpeak NG release tag → `.wasm` + `.data` +
> driver. Same script runs locally (macOS) and in CI (ubuntu-latest).
> Status: v0.1.0-draft · 2026-08-13

## Prerequisites

- macOS (local spike) or Linux (CI):
  - `brew install autoconf automake libtool` (macOS) / `apt install autoconf automake libtool` (CI)
  - git, bash
- Emscripten SDK: clone https://github.com/emscripten-core/emsdk, `emsdk install
  <pinned-version> && emsdk activate <pinned-version>` (~2–3 GB disk).
  The pinned version is recorded in `manifest.json` after each successful build.
- Disk: ~4 GB total (emsdk + two build trees).

## Pipeline overview

Two-stage build — the data package can **only** be produced by a native build:

```
stage 1 (native):  autoreconf → autogen → configure → make        → espeak-ng-data/
stage 2 (wasm):    ucd-tools via emconfigure → libespeak-ng.la    → link with glue.c
                   via emcc → espeak-ng.{js,wasm} + trimmed .data
```

## Steps

1. **Clone & pin.** `git clone https://github.com/espeak-ng/espeak-ng`; check out the
   pinned release tag (currently **1.52.0**); `git submodule update --init`
   (ucd-tools is a submodule since ~1.50 — a plain clone leaves `src/ucd-tools/`
   empty and the build fails later); record tag + commit SHA (they go into
   `manifest.json`).
2. **Fix autotools bootstrap:** `./autogen.sh && autoreconf -fvi` — in THIS order.
   autogen.sh creates `AUTHORS`/`NEWS`/`README` that automake requires (running
   autoreconf first aborts with "required file './AUTHORS' not found");
   autoreconf -fvi afterwards force-regenerates everything as copies — plain
   autogen output can contain symlinks to host GNU autotools files that break
   in clean environments (the ChromeOS port lesson).
3. **Native build (data stage):**
   `./configure --prefix=/usr --without-async --without-mbrola --without-sonic
   --disable-shared && make`
   (`--disable-shared`: only the static `libespeak-ng.a` is ever consumed, and
   macOS 26's ld rejects `-undefined dynamic_lookup` for shared-cache-eligible
   dylibs. Harmless on CI.)
   The native binary is a byproduct; the goal is `espeak-ng-data/` (phondata,
   phonindex, phontab, intonations — generated by eSpeak's own compile step).
4. **Native smoke test:**
   - `src/espeak-ng -v la "arma virumque cano"` (Latin voice exists and speaks)
   - `src/espeak-ng -v la "[[...]]"` (mnemonic input path works)
   - `src/espeak-ng --ipa ...` cross-check IPA output against our expectations
   - Verify the `la` phoneme inventory covers the full G2P output set (every IPA
     symbol we emit must have a mnemonic — see INTERFACE.md §5).
5. **ucd-tools: no separate build (step removed).** Since 1.50, espeak-ng
   vendors ucd-tools sources directly into libespeak-ng's `Makefile.am`
   (`src/ucd-tools/src/*.c` in `libespeak_ng_la_SOURCES`); the submodule's own
   autotools project is never invoked. Upstream's emscripten README still
   describes a separate ucd-tools cross-compile — it predates the vendoring.
   (Running ucd-tools' `autogen.sh` standalone on macOS fails anyway: its
   `ln -sf ChangeLog.md NEWS` clashes with the espeak-ng fork's `CHANGELOG.md`
   rename, and automake's required-file check is case-sensitive.)
6. **Cross-compile the library** (in a second, distclean'd copy of the tree —
   host objects from step 3 must not leak into the wasm link):
   `emconfigure ./configure --prefix=/usr --without-async --without-mbrola
   --without-sonic --disable-shared && emmake make src/libespeak-ng.la`
7. **Link wasm** with our own `glue.c` (not the upstream 2017 glue):
   ```
   emcc -O3 -c glue.c -o glue.o          # C mode keeps exports unmangled
   em++ -O3 -sWASM=1 -sMODULARIZE=1 -sEXPORT_ES6=1 -sALLOW_MEMORY_GROWTH=1 \
        -sENVIRONMENT=web,node \
        --preload-file espeak-ng-data-trimmed@/espeak-ng-data \
        -sEXPORTED_FUNCTIONS=[...] -sEXPORTED_RUNTIME_METHODS=[ccall,cwrap,FS] \
        glue.o .libs/libespeak-ng.a -o espeak-ng.js
   ```
   (`ENVIRONMENT=web,node`: node support lets CI run the smoke suite headless.
   Link step is em++, not emcc: libespeak-ng.a contains C++ objects — sized
   `operator delete` et al. — and emcc only pulls in the C++ runtime when it
   sees C++ inputs. glue.c stays C so its exports keep C linkage.)
8. **Trim data** via `trim-data.sh` (scripted, never manual — see below), then
   repackage `.data`.

## Data trimming (`trim-data.sh`)

Keep: `phondata`, `phonindex`, `phontab`, `intonations`, `lang/itc/la`.
Drop: all `*_dict` files, mbrola data, `voices/!v` variants, all other
language voices, `phondata-manifest` (build-time artifact).
Layout note (1.52): language voices moved from `voices/<code>` to
`lang/<family>/<code>` (la = `lang/itc/la`); this release has no
`voices/default` file, and the la voice references no `!v` variants.
Target: ≤ 2 MB trimmed; release acceptance = `.wasm` + `.data` ≤ 4 MB pre-gzip.

## Glue layer (`glue.c`, ~100 lines)

Exported functions: `espeakng_init` (espeak_Initialize with
`AUDIO_OUTPUT_SYNCHRONOUS` + synth callback), `espeakng_set_voice`,
`espeakng_synthesize` (espeak_Synth on the mapped `[[...]]` string, PCM
accumulated via callback), `espeakng_set_rate` / `espeakng_set_pitch`,
`espeakng_pcm` / `espeakng_pcm_len` / `espeakng_sample_rate` (buffer access),
`espeakng_terminate`.
(`AUDIO_OUTPUT_SYNCHRONOUS`, not RETRIEVAL: Synth blocks until the utterance
is complete — matches both `--without-async` and our whole-utterance model;
the same choice the upstream emscripten port made.)
`espeakng_synthesize` passes `espeakCHARS_UTF8 | espeakPHONEMES` — the
PHONEMES flag (0x100) is what makes the engine interpret `[[...]]` as
phoneme mnemonics. The CLI enables it in its default synth_flags; the
library does NOT, and without it `[[...]]` falls into the text/dictionary
path (silent with our dict-less trimmed data).
PCM: 22050 Hz / 16-bit signed / mono, whole-utterance buffered.

## Operational discipline

- Long builds run via `nohup bash build.sh > build.log 2>&1 &` with manual log
  tailing — never as agent-runtime background tasks (process-tree reaping risk).
- `build.sh` is the single source of truth: local spike and CI run the same script.
- CI: GitHub Actions, ubuntu-latest, pinned emsdk; on success upload artifacts;
  tag push → GitHub Release with `espeak-ng.wasm`, `espeak-ng.data`, `espeak-ng.js`,
  `espeak-wasm-driver.js`, `manifest.json`, `sha256sums.txt`.
- Reproducibility check: CI artifact SHA-256 must match a clean local build of the
  same tag + toolchain.

## Fallback path (if the spike stalls > 2 days)

Vendor a community build: candidate A = npm `espeak-ng@1.0.2` (ianmarmour);
candidate B = `echogarden-project/espeak-ng-emscripten`. Record source + SHA-256,
run the full acceptance suite, ship LICENSE alongside. Same acoustics (same
codebase), same acceptance criteria.

## Acceptance criteria

1. Clean-machine reproducibility (CI green, checksums match local).
2. Functional: ≥ 20 gold-standard IPA strings synthesize without error, PCM
   non-silent (RMS above threshold, checked programmatically), plausible durations.
3. Human spot-check: 5–10 items (incl. Aeneid I.1–7) reviewed by ear for phoneme
   identity and stress placement. (Robotic timbre is inherent to formant synthesis —
   not an acceptance item.)
4. Offline: after SW pre-cache, `playIPA` works with network disabled.
5. Size: `.wasm` + `.data` ≤ 4 MB pre-gzip.
